# 계획 — 로스터에 요원 장비(무기) 선택 붙이기

## 배경

킬 팀 편성에서 대부분의 요원은 무기를 **골라서** 장비한다. 예를 들어 죽음의 천사의
강습 인터세서 서전트는 원본 편성 가이드에 이렇게 적혀 있다.

```
• 강습 인터세서 서전트, 다음 각 선택지에서 하나씩 골라 장비합니다.
○ 한손 화염방사기, 중형 볼트 권총
○ 체인소드, 파워 피스트, 역장 무기, 선더 해머
```

지금 로스터는 요원을 "몇 명" 담았는지만 기록한다. 무엇을 들렸는지는 남지 않아,
로스터 화면이 그 요원의 **모든** 무기를 보여준다. 실제로 쓸 무기만 보이게 해야 한다.

## 데이터 조사 결과

계획을 세우기 전에 48개 팀 전체를 실측했다.

| 항목 | 수치 | 판단 |
|---|---|---|
| 요원 중 무기를 2종 이상 보유 | **431 / 492 (88%)** | 선택 UI 가 필요한 대상이 대부분 |
| 무기 개수 분포 | 2종 252명 · 3종 86명 · 4종 45명 · 5종 이상 48명 (최다 9종) | 목록형 UI 로 감당 가능 |
| 편성 가이드에 옵션(`○`)이 있는 팀 | 28 / 48 | 절반 조금 넘음 |
| 옵션 줄 수 | 147줄 | |
| **`• 요원명` 이 실제 요원 이름과 일치** | **29 / 492 (6%)** | ← **자동 파싱 불가의 결정적 근거** |
| `○` 안의 무기명이 실제 무기명과 일치 | 161 / 254 (63%) | 신뢰 불가 |
| 추출 과정에서 잘린 것으로 의심되는 heading | 7건 | 예: "선더 해머" → `선더` / `해머` 로 분리 |

불일치 사례를 보면 형식이 팀마다 제각각이다.

```
AEL-BOK: "절박한 복수자: 경비"                            ← 이름 뒤에 역할이 붙음
AEL-COR: "Shuriken rifle; shuriken pistol; power weapon"  ← 영문 · 세미콜론 구분
AEL-COR: "FATE DEALER"                                    ← 대문자 소제목
```

**결론: 편성 가이드 텍스트를 파싱해 선택지를 자동 생성하는 방식은 채택할 수 없다.**
요원 이름조차 6%만 맞는다. 억지로 맞추면 잘못된 선택지를 그럴듯하게 보여주게 되는데,
이는 아무것도 안 하는 것보다 나쁘다.

## 방안 비교

| 방안 | 내용 | 정확도 | 작업량 | 채택 |
|---|---|---|---|---|
| A. 가이드 텍스트 파싱 | `○` 줄을 파싱해 "이 중 하나" 그룹 생성 | 요원 매칭 6% — 불가 | 큼 | ✗ |
| B. 보유 무기 목록에서 직접 고르기 | 요원의 `weapons[]` 를 그대로 체크 목록으로 제시 | 데이터 그대로라 100% | 중 | ○ |
| C. 팀별 옵션표 수작업 작성 | 48팀 431명분 옵션을 사람이 정리 | 100% | 매우 큼 | ✗ |
| **B+** | B 를 쓰되 편성 가이드 원문을 선택 화면에서 함께 펼침 | 100% + 판단 근거 제공 | 중 | **채택** |

**권장: B+.** 선택지는 요원이 실제로 가진 무기 목록에서 고르게 하고, "몇 개를 골라야
하는가" 는 편성 가이드 원문을 바로 옆에 펼쳐 사람이 읽고 정하게 한다. 도구가 규칙을
아는 척하지 않는 대신, 규칙을 찾아 헤매지 않게 해준다.

## 저장 스키마 변경 (v1 → v2)

지금 구조는 **같은 요원 2명이 서로 다른 무기를 드는 경우를 표현할 수 없다.**
개수 맵을 인스턴스 배열로 바꾼다.

```jsonc
// v1 (현재)
{ "version": 1,
  "teams": { "IMP-AOD": {
    "operatives": { "IMP-AOD-ISGT": 2 },     // 2명 — 각자 뭘 들었는지 모름
    "equipment": ["IMP-AOD-CR"], "ploys": ["IMP-AOD-S-ADT"] } } }

// v2 (제안)
{ "version": 2,
  "teams": { "IMP-AOD": {
    "units": [                                // 인스턴스 단위
      { "uid": "u1", "opId": "IMP-AOD-ISGT", "weapons": ["볼트 소총", "체인소드"] },
      { "uid": "u2", "opId": "IMP-AOD-ISGT", "weapons": [] }   // [] = 미선택(전체 표시)
    ],
    "equipment": ["IMP-AOD-CR"], "ploys": ["IMP-AOD-S-ADT"] } } }
```

- `weapons` 는 **무기 행 이름**을 담는다. 한글표가 있으면 한글명, 없으면 영문명.
  무기에는 ID 가 없어 이름을 키로 쓸 수밖에 없다 — 원본 갱신으로 이름이 바뀌면
  그 선택은 버리고 미선택으로 되돌리며, 화면에 "선택 항목 1개가 더 이상 존재하지
  않아 해제됨" 을 알린다. 조용히 삼키지 않는다.
- `uid` 는 인스턴스 식별자. 팀 안에서 증가하는 카운터를 쓴다.
- 빈 배열 = 아직 안 고름. 로스터에서는 전체 무기를 보여주고 `미선택` 배지를 붙인다.

### 마이그레이션

`roster.js` 가 읽는 시점에 v1 을 만나면 자동 변환한다.

```
v1.operatives = { "X": 2 }  →  v2.units = [{uid, opId:"X", weapons:[]}, {uid, opId:"X", weapons:[]}]
```

담아둔 인원은 그대로 살아남고 무기만 미선택 상태가 된다. 변환 직후 저장해 다음부터는
v2 로 읽는다. 되돌릴 여지를 두기 위해 v1 원본은 `kt-index:roster:v1.bak` 로 한 번 남긴다.

## UI 설계

### 팀 상세 (`team.html`)

요원 카드의 담기 컨트롤을 인스턴스 단위로 확장한다.

```
┌────────────────────────────────────────────────────────┐
│ 인터세서 서전트(Intercessor Sergeant)      [− 2 +]     │
│                                     APL 3 · 이동 6" …  │
├────────────────────────────────────────────────────────┤
│ [1번째] [2번째]         ← 2명 이상 담았을 때만 노출     │
│ 무기                                                   │
│  ☑ 볼트 소총 (Bolt Rifle)      원거리 · 4 · 3+ · 3/4   │
│  ☐ 자동 볼트 소총              원거리 · 4 · 3+ · 3/4   │
│  ☑ 체인소드 (Chainsword)       근접   · 4 · 3+ · 4/5   │
│  ☐ 파워 피스트                 근접   · 4 · 4+ · 5/7   │
│                                                        │
│  ⓘ 편성 가이드 보기      ← 눌러 펼치면 원문 ○ 목록 표시 │
└────────────────────────────────────────────────────────┘
```

- 무기표 각 행 앞에 체크박스를 둔다. 담지 않은 요원은 비활성 — 먼저 담아야 고를 수 있다.
- 2명 이상이면 인스턴스 탭이 생기고 탭마다 선택이 따로 저장된다.
- "편성 가이드 보기" 는 `selectionGuide.blocks` 중 그 요원 이름이 들어간 문단을 펼친다.
  못 찾으면 가이드 전체를 펼친다 — **추측해서 잘라내지 않는다.**

### 로스터 (`roster.html`)

- 인스턴스마다 카드를 그리고 선택한 무기만 표로 보여준다.
- 미선택 인스턴스는 전체 무기 + `미선택` 배지, 눌러 팀 상세로 이동.
- 팀 헤더에 `무기 미선택 2명` 요약을 덧붙인다.

## 검증 계획

- **마이그레이션**: v1 데이터를 심어 두고 페이지를 열어 인원이 보존되는지 확인
  (`{"IMP-AOD-ISGT":2}` → 인스턴스 2개, 무기 미선택).
- **인스턴스 독립성**: 같은 요원 2명에게 다른 무기를 지정하고 새로고침 후 유지 확인.
- **이름 변경 내성**: 저장된 무기명을 없는 값으로 바꿔 넣고, 죽지 않고 미선택으로
  되돌아가며 안내가 뜨는지 확인.
- **모바일**: 360 · 375 폭에서 체크박스가 카드형 무기표를 깨지 않고 가로 스크롤이
  생기지 않는지 확인.
- **저장 실패**: localStorage 차단 상태에서 경고가 뜨는지 확인.

## 하지 않을 것 (명시적 비목표)

- **편성 규칙 자동 검증.** "○ 중 하나씩" 같은 제약은 데이터가 자연어라 강제할 수 없다.
  인원 정원(`size.total`) 초과만 지금처럼 표시한다.
- **가이드 텍스트에서 선택지 자동 추출.** 위 조사대로 정확도가 낮다.
- **여러 로스터 이름 붙여 저장 · 공유 링크 · 인쇄.** 별도 작업으로 남긴다.
